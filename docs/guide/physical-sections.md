# 动作分段（Sections）与动态调速

## 为什么不硬编码阶段语义？

许多动作插件喜欢在动画资产中直接写死“前摇”、“判定”、“后摇”、“蓄力循环”等固定枚举。

但在实际动作游戏项目中，这种硬编码往往带来灵活性受限：
1. **多段派生与组合技难以表达**：三连斩、翻滚接突刺等复合动作，阶段划分复杂，无法用几个简单的枚举框死。
2. **同一动作在不同情境下的复用**：同一个倒地翻滚动作，在普通闪避状态下是常规位移，在受击起身状态下可能是后半段带有无敌帧的受身动作。

### CwcMontage 的设计：基于时间切分点 (Sections)

在 `CwcMontage` 中，资产内部仅维护一组切分时间戳（`SplitTimestamps`）：
例如一段 1.5 秒的挥刀动作，配置了切分点 `[0.4s, 0.7s]`，系统会自动划分出 3 个分段：
- **Section 0**: `[0.0s, 0.4s)`
- **Section 1**: `[0.4s, 0.7s)`
- **Section 2**: `[0.7s, 1.5s]`

资产本身只做时间划分，由具体的技能系统或业务脚本赋予逻辑意义（例如将 Section 0 作为前摇，Section 1 作为打击判定帧，Section 2 作为后摇收招）。

## 分段动态调速 (SyncSectionDuration)

在动作游戏中，经常出现根据数值调整动作节奏的需求（例如角色获得了攻速提升 Buff，要求前摇从 0.4 秒缩短至 0.25 秒，但打击判定帧和后摇收招保持原速以保持打击手感）。

如果直接缩放整个动画的全局 `Speed`，会导致所有阶段同时变快，击中感失真。

### 核心 API：`SyncSectionDuration`

`CwcMontage` 允许针对单个分段独立设置期望时长：

```csharp
// 将 Section 0（前摇）的播放时长调整为 0.25 秒
handle.SyncSectionDuration(0, 0.25f);
```

### 换算原理
设分段 $i$ 的原始资产时长为 $D_{raw}$，期望目标时长为 $D_{target}$：

$$\text{PlaybackRate} = \frac{D_{raw}}{D_{target}}$$

当播放器进入该分段的时间区间时，会自动应用此速率倍率，精准匹配玩法数值需求，无需美术人员重新切动画或导出 FBX。

## 外部主动跳转与进度驱动

除了正常播放推进，外部技能脚本可以通过句柄（`MontageHandle`）灵活控制播放位置：

### 1. 立即跳转到指定分段 (JumpToSection)
```csharp
// 瞬间切入第 2 分段（例如命中目标或触发取消连招后提前进入出招判定段）
handle.JumpToSection(1);
```

### 2. 外部蓄力进度驱动 (EvaluateSectionProgress)
对于蓄力型技能（由玩家按键时长或蓄力进度条驱动动作演进）：
```csharp
// 将 Section 1 的播放进度锁定在 75%
handle.EvaluateSectionProgress(1, 0.75f);
```
此方法允许外部逻辑根据按键输入绝对驱动姿态采样，蓄力松手后再恢复正常播放，避免了蓄力段循环播放时的抽搐与错位。
