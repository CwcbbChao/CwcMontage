# 去语义化物理分段与自适应时钟

## 什么是“去语义化物理分段”？

传统动画系统或动作插件通常倾向于给动画片段硬编码业务标签，例如“前摇段 (Anticipation)”、“有效判定段 (Active)”、“后摇收招段 (Recovery)”甚至“蓄力循环段 (Charge Loop)”。

然而在真实的动作游戏项目中，这种**强语义绑定**会带来严重的弊端：
1. **玩法变化导致资产报废**：策划如果将一个三段斩击改成带有二段派生的复合技能，原有的固定枚举标签立即失效，必须推翻资产重做。
2. **多系统复用困难**：同一个翻滚动作，在普通移动状态下作为“战术翻滚”（允许全程闪避），在受击状态下作为“受身翻滚”（仅后半段允许受身）。硬编码语义会让动画资产失去通用性。

### CwcMontage 的设计哲学：客观几何切分

在 `CwcMontage` 中，资产内部只记录一组浮点数组 `_splitTimestamps`（几何切分时间戳）。
例如一段 1.5 秒的挥刀动作：
- 切分点：`[0.4s, 0.7s]`
- 自动派生出 3 个物理分段：
  - `Section 0`: `[0.0s, 0.4s)`
  - `Section 1`: `[0.4s, 0.7s)`
  - `Section 2`: `[0.7s, 1.5s]`

**资产本身不定义任何语义**。由外部调用它的技能系统去赋予语义：“对于技能 A，Section 0 是前摇；对于技能 B，Section 0 是施法吟唱”。

## 自适应时钟缩放 (Adaptive Time Warping)

在动作游戏中，经常出现策划修改动作帧数需求的情况（例如玩家佩戴了“攻速提升 20%”装备，要求前摇从 0.4 秒压缩为 0.3 秒，但判定段与后摇段保持原速）。

传统的解决办法往往是去缩放整个动画的 `speed`，但这会导致判定段也变快，产生打击手感失真。

### 核心 API：`SyncSectionDuration`

`CwcMontage` 提供了分段级别的自适应时钟缩放功能：

```csharp
// 将 Section 0 的播放时长自适应校准为 0.25 秒
handle.SyncSectionDuration(0, 0.25f);
```

### 换算原理与公式
设分段 $i$ 的原始物理几何时长为 $D_{raw}$，目标期望时长为 $D_{target}$：

$$\text{TimeScale} = \frac{D_{raw}}{D_{target}}$$

当播放器推进到该物理分段的时间区间时，底层驱动的 `AnimationClipPlayable` 的播放速率将平滑切换为此缩放系数。表现层完全自动化完成美术时间与数值时间的匹配，消除团队内耗。

## 外部主动跳转与进度驱动

除了自然推进时间，外部系统可以通过句柄（`MontageHandle`）完全主导分段流转：

### 1. 立即跳转到指定分段 (JumpToSection)
```csharp
// 瞬间切入第 2 分段（例如玩家成功连招，取消当前前摇立即出招）
handle.JumpToSection(2);
```

### 2. 外部蓄力进度驱动 (EvaluateSectionProgress)
对于蓄力型技能（玩家按住按键蓄力，根据按键时长或外部数值驱动）：
```csharp
// 将 Section 1 的播放进度锁定为 75%
handle.EvaluateSectionProgress(1, 0.75f);
```
此方法将停止自动时间推进，转由外部逻辑以绝对进度驱动表现层骨骼姿态，彻底解决传统自动循环造成的动画跳帧与对齐失真。
