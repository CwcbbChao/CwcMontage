# 区间扫掠无漏帧算法 (Interval Sweep)

在动作游戏中，音效、粒子、判定盒（Hitbox）以及受击保护的生效时机往往精确到毫秒级。

然而，在游戏运行遭遇极端卡顿、垃圾回收（GC Spike）或设备低性能降频导致掉帧时（例如当帧卡顿 100ms），传统的动画事件系统极易崩溃。

---

## 传统“瞬时点采样”的缺陷

大多数轻量插件或 Unity 自带的 Animation Event 采用的是**当帧时间瞬时比较**或**离散单点比较**：

```
Frame 0: Time = 0.10s
[严重卡顿 100ms]
Frame 1: Time = 0.20s

若某个判定盒的生效区间为 [0.12s, 0.18s]:
- 0.10s 处于生效前
- 0.20s 已处于生效后
结果: 该事件被彻底跳过，玩家打中敌人却未造成伤害！
```

更为严重的是，如果系统触发了 `OnEnter` 却在下一帧直接跨越了 `OnExit`，会导致临时生成的特效或音效永远残留在场景中（无法被销毁）。

---

## 区间扫掠算法核心机制

`CwcMontage` 采用严格的**半开增量区间扫掠算法（Incremental Half-Open Interval Sweep）**：

对于当前帧，播放器记录：
- 上一帧的局部时间：$T_{last}$
- 当前帧推进到的局部时间：$T_{curr}$
- 当帧扫掠区间定义为：$I_{frame} = (T_{last}, T_{curr}]$

对于任意一个在时间区间 $[S, E)$ 生效的 ActionBlock，其生命周期的转移条件被严格数学化：

```mermaid
flowchart TD
    A[检查当帧扫掠区间 (LastTime, CurrentTime]] --> B{当前时间是否进入区间 [S, E)?}
    B -->|是，且尚未处于激活态| C[调用 OnEnter\n标记为 Active 状态]
    C --> D{当前时间是否依然处于 [S, E)?}
    B -->|否，但之前已处于激活态| E[调用 OnExit\n清除 Active 标记]
    D -->|是| F[调用 OnUpdate]
    D -->|否，当帧即跨越了整个 Block| E
```

### 1. 极端卡顿下的“必成对触发”保证
即使由于极端掉帧，当帧时间从 $0.10s$ 瞬间暴增至 $0.50s$ 并完全跨越了 $[0.15s, 0.25s]$ 的动作块：
算法判定当帧扫掠区间 $(0.10, 0.50]$ 与该 Block 存在覆盖关系，内核将**保证在当帧顺序执行**：
1. 先调用 `OnEnter`（初始化资源）
2. 紧接着调用 `OnExit`（清理资源）

**结论：100% 杜绝了对象残留与内存泄漏，保证状态机的数学闭环。**

---

## 时间倒放与瞬间 Seek 兼容

该算法天然对称支持反向推进（$T_{curr} < T_{last}$）与瞬移跳转：
- 当时间反向回退时，扫掠区间自动调整为 $[T_{curr}, T_{last})$。
- 当发生强行跳转（Seek / JumpToSection）时，内核先将当前所有处于 Active 状态的 Block 优雅触发 `OnExit`，完成清理后再重新定位到目标时间戳，无任何副作用残留。
